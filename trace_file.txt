! Purpose
!   Validates the direct-mapped cache simulator (cache_sim) for a
!   write-allocate / write-through cache.
!
! Command line used for validation:
!   cache_sim trace_file.txt 256 16
!
!   blocks_in_cache = 256          (8 index bits)
!   words_in_block  = 16           (4 offset bits)
!   tag bits        = 32 - 8 - 4 = 20
!
! Address layout (32 bits, written as 8 hex digits)
!
!     digit 7 6 5 4 3      digit 2 1      digit 0
!     +----------------+   +-------+      +---+
!     |     Tag        |   | Index |      |Off|
!     +----------------+   +-------+      +---+
!     20 bits = 5 hex     8 bits = 2 hex   4 bits = 1 hex
!
!   so an address xxxxxIIo decodes as
!     tag    = 0xxxxxx     (top 5 hex digits)
!     index  = 0xII        (next 2 hex digits)
!     offset = 0xo         (last hex digit)
!
! Decision paths exercised (all 6 branches of the flowchart):
!   1. Read  hit                                   (RH)
!   2. Read  miss on invalid block                 (RM-invalid)
!   3. Read  miss on valid block, different tag    (RM-valid)
!   4. Write hit (writes 1 word through to memory) (WH)
!   5. Write miss on invalid block                 (WM-invalid)
!   6. Write miss on valid block, different tag    (WM-valid)
!
! Note on counter uniqueness
!   For a write-allocate / write-through cache, every CPU write produces
!   exactly one external memory write, so by construction
!       NWA = NCWH + NCWM = CPUW.
!   This single equality is a structural property of the policy and cannot
!   be broken by trace design.  Every other pair of counter values is
!   distinct, so any counter swap that does not involve the CPUW <-> NWA
!   pair will change the simulator's output.
!
! Expected simulator output:
!   CPUR =   5
!   CPUW =  10
!   NCRH =   2
!   NCRM =   3
!   NCWH =   4
!   NCWM =   6
!   NRA  = 144
!   NWA  =  10        (= CPUW, see note above)
!   WIB  =  16
!   BIC  = 256
!   file = trace_file.txt
! ============================================================================
